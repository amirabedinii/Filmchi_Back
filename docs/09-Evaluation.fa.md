# ۰۹. مستند ارزیابی

**English:** [09. Evaluation Documentation](09-Evaluation.md)

---

این سند روش‌های **ارزیابی مهندسی** سیستم را شرح می‌دهد: اندازه‌گیری تأثیر کش، روش رسیدن به پرامپت مناسب، و معیارهای قابل گزارش.

---

## ۱. ارزیابی کش (تأثیر کش)

### ۱.۱ هدف
ثابت کردن اینکه کش چقدر تأثیر مثبت روی **زمان پاسخ** و **کاهش فراخوانی به TMDB** دارد.

### ۱.۲ معیارها

| معیار | تعریف | هدف |
|:------|:------|:----|
| **تأخیر (میانگین)** | زمان پاسخ سرور برای یک درخواست (مثلاً GET /movies/search?q=...) | کاهش محسوس با کش فعال |
| **نرخ برخورد کش** | نسبت درخواست‌هایی که از Redis/DB پاسخ داده شده‌اند به کل درخواست‌ها | افزایش با استفادهٔ تکراری |
| **تعداد فراخوانی TMDB** | تعداد فراخوانی به TMDB در یک سناریو | کاهش با کش |

### ۱.۳ روش اجرا

**پیش‌نیاز:** سرور در حال اجرا، Redis روشن، یک بار کش خالی است.

۱. **سناریو الف — بدون کش**

   ```bash
   CACHE_ENABLED=false npm run start:dev
   ```
   سپس با ابزار (مثلاً `scripts/benchmark-cache.sh`) یا دستی چند درخواست تکراری به یک endpoint (مثلاً جستجو یا جزئیات فیلم) بفرستید و زمان پاسخ را ثبت کنید.

۲. **سناریو ب — با کش**

   ```bash
   CACHE_ENABLED=true npm run start:dev
   ```
   همان درخواست‌ها را دوباره اجرا کنید:
   - بار اول: cache miss → زمان مشابه یا کمی بهتر (به‌خاطر عدم فراخوانی اضافه).
   - بار دوم و بعد: cache hit → زمان پاسخ باید به‌طور محسوس کمتر باشد.

۳. **مقایسه**
   - میانگین زمان پاسخ (ms) در حالت بدون کش در مقابل با کش (بعد از warm).
   - تعداد درخواست به TMDB در هر حالت (از لاگ یا با غیرفعال کردن کش و شمارش).

### ۱.۴ اسکریپت بنچمارک

از اسکریپت زیر برای مقایسهٔ سریع استفاده کنید (جزئیات در `scripts/README.md` یا `scripts/README.fa.md`):

```bash
./scripts/benchmark-cache.sh
```

خروجی نمونه:
- زمان هر درخواست (با کش / بدون کش).
- میانگین و مقایسه.

### ۱.۵ گزارش نمونه (قالب)

| حالت | درخواست | میانگین (ms) | توضیح |
|:------|:--------|:------------|:------|
| بدون کش | ۱۰ بار همان جستجو | ~۸۰۰ | هر بار TMDB |
| با کش (سرد) | ۱ بار جستجو | ~۷۵۰ | یک بار TMDB + set کش |
| با کش (گرم) | ۹ بار همان جستجو | ~۱۵ | همه از Redis |

**نتیجه:** کش برای درخواست‌های تکراری کاهش قابل توجه زمان پاسخ و کاهش فشار به TMDB را نشان می‌دهد.

## ۲. ارزیابی پرامپت (مهندسی پرامپت)

### ۲.۱ هدف
ثبت کنیم **چطور به پرامپت مناسب رسیدیم** و معیارهای کیفیت پیشنهادها چیست.

### ۲.۲ معیارهای کیفیت پرامپت

| معیار | تعریف | نحوه ارزیابی |
|:------|:------|:-------------|
| **تطابق با درخواست** | پیشنهادها با «حال و هوای» کاربر (مثلاً غمگین/شاد) همخوانی دارند | بررسی دستی روی نمونه کوئری‌ها |
| **تعداد پیشنهاد با پوستر** | بعد از غنی‌سازی TMDB، چند مورد poster دارند | شمارش در پاسخ API |
| **زبان دلیل (reason)** | برای زبان fa، دلیل به فارسی باشد | بررسی دستی |
| **تنوع (ایرانی + بین‌المللی)** | برای کوئری فارسی، ترکیب فیلم ایرانی و غیرایرانی | بررسی دستی لیست خروجی |

### ۲.۳ روش رسیدن به پرامپت فعلی

۱. **نسخه اولیه:** پرامپت ساده «بر اساس این کوئری چند فیلم پیشنهاد بده».
۲. **مشکل:** برای کوئری «فیلم غمگین» گاهی فیلم شاد پیشنهاد می‌شد → **رعایت صریح درخواست کاربر** به پرامپت اضافه شد (بندهای CRITICAL GUIDELINES).
۳. **زبان فارسی:** درخواست برای دلیل به فارسی و گنجاندن ۲–۳ فیلم ایرانی → اضافه شدن `languageInstruction` و بندهای مربوط به سینمای ایران در `llm.service.ts`.
۴. **یکتایی پاسخ:** برای کاهش کش شدن پاسخ در سمت مدل، `Request ID` به پرامپت اضافه شد.
۵. **اسکیما:** خروجی به صورت JSON با فیلدهای `title`, `year`, `reason` تا پارس و غنی‌سازی با TMDB ممکن باشد.

**مستندات کد:** `src/llm/services/llm.service.ts` — متد `buildMovieRecommendationPrompt`.

### ۲.۴ مجموعه کوئری‌های نمونه برای ارزیابی

برای ارزیابی دستی یا نیمه‌خودکار از این کوئری‌ها استفاده کنید:

| شناسه | کوئری (نمونه) | زبان | انتظار |
|:------|:--------------|:-----|:------|
| Q1 | فیلم غمگین دهه ۹۰ | fa | فقط فیلم‌های غمگین، دلیل به فارسی، حداقل ۱–۲ فیلم ایرانی |
| Q2 | Sad movies from the 80s | en | فیلم‌های غمگین دهه ۸۰، دلیل به انگلیسی |
| Q3 | کمدی رمانتیک ایرانی | fa | ترکیب ایرانی و در صورت امکان بین‌المللی، دلیل فارسی |
| Q4 | Scary movies for Halloween | en | فیلم ترسناک، تنوع سال |

### ۲.۵ نحوه اجرای ارزیابی پرامپت

۱. سرور و سرویس LLM (Ollama/OpenRouter) را روشن کنید.
۲. برای هر کوئری در جدول بالا:
   - یک بار `POST /api/v1/recommendations` با body `{ "query": "..." }` بفرستید.
   - پاسخ را ذخیره کنید (فایل یا لاگ).
۳. چک‌لیست ارزیابی:
   - [ ] تعداد پیشنهادها (حداقل ۳، حداکثر ۷).
   - [ ] آیا دلایل با درخواست (غمگین/شاد/ترسناک/...) مطابقت دارند؟
   - [ ] برای زبان fa، دلیل به فارسی است؟
   - [ ] برای fa، حداقل یک فیلم ایرانی در لیست هست؟
   - [ ] بعد از غنی‌سازی، چند مورد poster دارند؟

نتایج را می‌توان در یک جدول یا فایل متنی (مثلاً `scripts/prompt-evaluation-results.md`) ثبت کرد.

### ۲.۶ تکرار و بهبود

- اگر معیاری برآورده نشد، تغییر در پرامپت در `buildMovieRecommendationPrompt` اعمال شود.
- پس از تغییر، دوباره همان کوئری‌های نمونه اجرا و مقایسه شود.
- نسخه پرامپت و تاریخ در کامنت یا چنگ (changelog) ثبت شود.

---

## ۳. خلاصه و ارجاع

- **کش:** معیارها = زمان پاسخ، نرخ hit، تعداد فراخوانی TMDB. روش = مقایسه با/بدون کش و استفاده از `scripts/benchmark-cache.sh`.
- **پرامپت:** معیارها = تطابق با درخواست، زبان، تنوع ایرانی/بین‌المللی، تعداد با پوستر. روش = کوئری‌های نمونه + چک‌لیست دستی و تکرار.

برای جزئیات تست واحد و E2E به `06-Testing.md` یا `06-Testing.fa.md` مراجعه کنید.
